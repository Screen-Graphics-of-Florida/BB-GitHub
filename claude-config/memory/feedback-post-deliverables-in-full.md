When Bill asks for a summary, a document, a script, or anything else with real content, **write the
full text into the chat as well as to the file.** Never answer with only a file path and a
description of what is in it. He said this on 2026-08-27 - "I've said you're always supposed to post
it in full here" - after I wrote a project summary to disk and only described it.

**Why:** he reads and copies from the chat. A path means he has to leave the conversation, open the
file, and scroll it before he can even judge whether the content is right. It also hides errors from
him - he cannot correct what he cannot see. This holds even when the file is the deliverable and the
destination is somewhere else entirely, such as Evernote or a PowerPoint.

**How to apply:** save the file when a file is wanted, then post the complete content in the
response. Do not abridge it, do not summarize it, and do not offer to post it on request. If it is
long, it is still posted in full. Related: [[feedback-full-links]] and
[[feedback-caveats-before-code]] - same underlying preference, everything he needs is in the
message, not behind a lookup.
